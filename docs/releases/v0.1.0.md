First public pre-release of KubeVirt NetDoctor: a read-only kubectl plugin that explains
how a KubeVirt VM is wired into the network and what is wrong with it, with evidence.

## Highlights

- **Kubernetes diagnostics**
  - VM/VMI and virt-launcher discovery (migration-aware), Multus requests and status;
  - NetworkAttachmentDefinition parsing (bridge, OVS, macvlan, ipvlan, SR-IOV, host-device; IPAM);
  - structured findings with a certainty category (Confirmed, Suspected, Unavailable),
    expected state and next step.
- **Host snapshot** (`host collect`): links, Linux bridges and VLAN tables, VLAN
  sub-interfaces, bonds and LACP, routes, and OVS bridges, ports, interfaces, bonds and flows.
  It uses a fixed allowlist of read-only commands and never a shell.
- **Diagnose**:
  - VLAN, MTU, bond/LACP and OVS port checks against the node;
  - route analysis toward a destination;
  - optional expectations file.
- **Topology**: a graph whose edges are labeled Observed, Declared or Inferred, with
  text, JSON, Graphviz DOT and Mermaid output.
- **Kernel tracer (experimental)**, `trace` → `host trace --plan` → `diagnose --trace`:
  - CO-RE eBPF on passive tracepoints only: drops with the kernel drop reason, TCP
    retransmits, resets and state changes, and per-interface counts;
  - filtered in the kernel to the VM's virt-launcher network namespace and addresses;
  - every event attributed as DirectlyAttributed, Correlated, Ambiguous or Unattributed;
  - bounded, with lost-event accounting, and measures its own overhead.
- **`capabilities` / `host capabilities`**: what your RBAC and your node's kernel allow,
  including a verifier load of the BPF programs.
- **`report`**: a combined report or a `.tar.gz` bundle with a SHA-256 manifest and
  optional consistent IP/MAC redaction.
- **Exit codes**: `--fail-on info|warning|error` exits 2 when findings reach the threshold.

## Validation

- Unit, golden, fake-cluster and network-namespace tests.
- Real-kernel eBPF tests, run as root in CI on GitHub-hosted runners.
- A live KubeVirt lab, scripted in `hack/lab`: Kubernetes 1.33, KubeVirt v1.10.0, Multus
  with Linux bridge and OVS CNI, VLAN trunks and a bond. **43 of 43 checks passed:**
  - healthy baseline;
  - faults: missing NAD, VLAN mismatches, VLAN filtering off, OVS re-tag, bridge down,
    bond member down or removed, MTU expectation;
  - a kernel trace of a real virt-launcher pod (0.053% of one CPU core);
  - a redacted report bundle.

## Known limitations

- **Early release.** The CLI and JSON schemas (`v1alpha1`) may change between minor
  versions.
- **No connectivity testing.** No command sends traffic yet; an opt-in `probe` is planned.
- **Guest TCP is invisible to the host tracer.** A VM's TCP stack runs in the guest, so
  for VM traffic the tracer sees host-path drops and interface counts only.
- **Partial plugin coverage.** OVN-Kubernetes and Kube-OVN are designed but not
  implemented. Calico, Cilium and Flannel are covered through the node's route view only.
- **Not yet validated:** live migration and LACP on real NICs.
- The full coverage map is in `docs/implementation-status.md`.
